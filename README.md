# Песочница для Экспертных систем МАС

## Установка зависимостей
`pip install -r requirements.txt` 

Выберете версию модели NLP:
- `python -m spacy download ru_core_news_sm`
- `python -m spacy download ru_core_news_md`
- `python -m spacy download ru_core_news_lg`

## Запуск программы
Для Windows: `python main.py`

Для Mac: `python3 main.py`

## Функциональные требования

- анализ файла и поиск в нем фрагментов соответствующим правилам БЗ;
- наполнение базы знаний:
  - формирование набора переменных рабочей памяти (при сохранении фиксируется автор или источник знаний, имя и дата файла / массива БЗ);
  - сохранение фактов (при сохранении фиксируется автор, имя и дата файла);
  - формирование и сохранение правил в БЗ (при сохранении фиксируется автор и/или источник знаний, имя и дата файла).
- трассировка базы правил одного эксперта (агента):
  - выявление схожих правил;
  - выявление конфликтных (противоречащих или схожих) правил. В случае выявления конфликтных правил или схожих - предусмотреть возможность изменения (корректировки) приоритета и самих правил пользователем (аналитиком / инженером по знаниям / экспертом).
- трассировка базы правил нескольких агентов (базы знаний агентов выбирает пользователь) выявление схожих и конфликтных правил;
- реализовать возможность просмотра локальных баз знаний агентов (конкретного агента) и общей базы знаний всех агентов предметной области (задачи);
- предусмотреть возможность ввода пользователем новых предметных областей (новой области, агентов и наполнение их рабочих памятей и баз знаний);
- поиск правил агента или агентов (всех или выбранных), которые содержат обращение или изменение выбранных переменных рабочей памяти;
- реализовать прямой вывод по базе знаний выбранной предметной области;
- реализовать обратный вывод по базе знаний выбранной предметной области;
- реализовать подсистему объяснения, выполняющую пошаговое фиксирование вывода (прямого и обратного);
- \* в случае если при выводе участвуют несколько агентов реализовать отображение сцены коммуникации.

Дополнительные задачи:
1. Для демонстрации работы приложения требуется предусмотреть пример (для любой предметной области (как варианты - строительство/ремонт, диагностика неисправностей (поломок) техники (авто, компьютерной), медицинская диагностика и т.д.).

Критерии оценивания:
1. Анализ предметной области;
2. Выбор методов / средств решения задачи;
3. Разработка алгоритмов и программная реализация (модели или приложения);
4. Проведение экспериментов с моделью;
5. Тестирование приложения;
6. Анализ результатов и формулирование рекомендаций;
7. Оформление документации.
